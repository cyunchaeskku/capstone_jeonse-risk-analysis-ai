# 실제 사례 수집 지시서 (웹 브라우징 에이전트용)

법원경매 물건에서 전세사기 위험 분석 엔진의 평가용 케이스 **4건**을 수집한다.

---

## 0. 왜 경매 물건인가

평가에는 "이 매물이 위험했는가"에 대한 **정답 라벨**이 필요하다. 경매로 넘어간 물건은
결과가 이미 확정돼 있어 추측 없이 라벨링할 수 있다. 특히 **대항력 있는 임차인이 배당요구를
하지 않은 물건**은 낙찰자가 보증금을 전액 인수해야 해서 아무도 입찰하지 않고, 그 유찰
기록이 "임차인이 보증금을 회수하지 못했다"는 증거가 된다.

**이미 확보한 1건** (중복 수집 금지):
인천지법 2021타경521675, 다세대, 집합건물, 근저당 0원, 전세가율 100.4%, 12회 유찰.
→ "등기부가 깨끗한 깡통전세" 유형.

---

## 1. 수집처

대법원 법원경매정보 <https://www.courtauction.go.kr/> → **경매물건 > 물건상세검색**
로그인·회원가입 불필요. 모든 서류 무료.

---

## 2. 검색 조건

| 항목 | 값 | 이유 |
|---|---|---|
| 용도 | 다세대, 연립, 오피스텔, 다가구, 단독 | 전세 계약 대상 |
| **매각기일** | **오늘부터 14일 이내** | 서류 열람 창(§3) |
| 감정평가액 | 1억 ~ 6억 | 전세 수요 구간 |
| 소재지 | 제한 없음 (수도권 권장) | 사례가 많다 |

### 서류 열람 창 — 검색 조건에 매각기일을 반드시 넣는 이유

| 서류 | 열람 가능 시점 |
|---|---|
| 매각물건명세서 | 매각기일 **1주** 전 ~ 매각기일 |
| 현황조사서, 감정평가서 | 매각기일 **2주** 전 ~ 매각기일 |
| 사건상세조회, 등기기록 열람 | 항상 |

매각기일이 2주 넘게 남은 물건은 **현황조사서를 볼 수 없고, 거기에만 있는 임차인 전입일자를
얻지 못한다.** 전입일자가 없으면 §5 계약 시점 복원이 불가능해 케이스로 쓸 수 없다.
기일이 먼 물건은 시간 낭비이므로 처음부터 걸러라.

---

## 3. 선별 절차

### 3-1. 1차 — 목록 화면에서 유찰 횟수 역산

목록에 `감정평가액`과 `최저매각가격`이 나온다. 비율로 유찰 횟수를 계산한다.

```
비율 = 최저매각가격 ÷ 감정평가액
유찰 횟수 n:  비율 ≈ 0.7ⁿ  (저감률 30%)  또는  0.8ⁿ  (저감률 20%)
```

저감률은 법원마다 다르다. 두 식에 다 넣어보고 **정수 n에 더 정확히 맞는 쪽**을 채택하라.

> 검증 예: 감정가 361,000,000 / 최저가 60,566,000 → 비율 0.1678.
> 0.7⁵ = 0.168 (오차 있음), 0.8⁸ = 0.16777 → 361,000,000 × 0.8⁸ = 60,565,750 ≈ 일치.
> 따라서 저감률 20%, **8회 유찰**.

| 비율 | 유찰 | 처리 |
|---|---|---|
| < 30% | 4회+ | **위험 라벨 후보 — 우선 조사** |
| 30~50% | 2~3회 | 위험 라벨 후보 |
| 50~70% | 1~2회 | 후순위 |
| 70~100% | 0~1회 | **안전 대조군 후보** (§4 D유형으로 1건 필요) |

### 3-2. 2차 — 사건상세조회 > 문건/송달내역에서 즉시 제외

유찰이 많은 이유가 임차인 보증금 인수가 아니라 **물건 자체의 하자**일 수 있다. 그런 물건은
우리 규칙(R1~R8)이 다루는 위험이 아니므로 평가에 쓸 수 없다.

**다음이 보이면 즉시 버리고 다음 물건으로 간다:**

- `유치권신고서 제출` → 유치권 물건
- `공유자 우선매수신고` → 지분 매각
- 목록 표시가 `토지만 매각`, `건물만 매각`, `지분 매각`
- 매각물건명세서 비고란에 `법정지상권`, `분묘기지권`

**반대로 다음은 좋은 신호:**

- `권리신고 및 배당요구신청서 제출` → 임차인이 배당요구함 → **보증금 금액이 서류에 나온다**
- 임차인 관련 문건이 전혀 없음 → 배당요구 안 함 → 낙찰자 전액 인수 (강한 위험 라벨)

### 3-3. 3차 — 서류에서 값 추출

| 서류 | 추출할 값 |
|---|---|
| 감정평가서 (또는 물건기본정보) | 감정평가액 |
| **현황조사서** | 임차인 **전입일자**, 점유 용도(주거/업무), 보증금, 확정일자 |
| **매각물건명세서** | **최선순위 설정 일자와 종류**, 배당요구 여부, 인수되는 권리, 비고란 |
| 등기기록 열람 | 근저당 **채권최고액**, 설정일자, 공동담보 물건 수, 갑구 소유자 |
| 물건기본정보 | 물건종류(다세대/다가구/오피스텔), 사건번호, 사건접수일 |

**보증금란이 공란이면** 매각물건명세서·현황조사서 양쪽 모두 확인하라. 둘 다 없으면
`deposit_krw`를 `null`로 두고 `provenance`에 "미확인"으로 적는다. **추측해서 채우지 마라.**

## 4. 다양성 요구 — 4건은 서로 다른 유형이어야 한다

같은 유형 4건은 1건과 정보량이 같다. 아래 A~D를 **각 1건씩** 찾아라.
완전히 못 채우면 억지로 맞추지 말고, 찾은 것과 못 찾은 것을 보고하라.

| # | 유형 | 고르는 기준 | 검증 목적 |
|---|---|---|---|
| **A** | 근저당 과다형 | 최선순위가 **근저당**이고 채권최고액 ÷ 감정가 > 0.6 | R2 단독 `fail` — 실제 사례 0건 |
| **B** | 다가구 선순위형 | 물건종류 **다가구/단독**, 임차인 여러 명 | R8 — 피해 규모 최대 유형인데 검증 0건 |
| **C** | 권리침해형 | 최선순위가 **압류·가압류·가처분·신탁**이고, 그 접수일이 **임차인 전입일보다 앞섬** | R4 오버라이드 |
| **D** | 안전 대조군 | 유찰 0~1회 + 배당요구 있음 + 보증금÷감정가 < 0.7 | **오탐 측정** — 현재 위험 라벨만 있어 오탐을 못 잰다 |

C의 "전입일보다 앞섬" 조건이 중요하다. 전입일보다 **뒤**에 설정된 권리는 계약 시점에
존재하지 않았으므로 §5에 따라 제거되고, 그러면 R4를 검증하지 못한다.

---

## 5. 계약 시점 복원 — 가장 중요한 규칙

경매 물건의 등기부에는 **경매개시결정과 그 이후의 압류가 이미 올라와 있다.** 그대로
입력하면 R4가 `fail`이 되어 "결과를 보고 결과를 맞히는" 순환논증이 되고 데이터가 무의미해진다.

> **임차인 전입일자보다 늦게 접수된 등기는 전부 제외한다.**

평가가 묻는 질문은 "경매에 넘어간 물건인가"가 아니라
**"임차인이 계약하던 시점에 이 시스템을 썼다면 막을 수 있었는가"** 이기 때문이다.

제외 대상 예시: 경매개시결정, 전입일 이후 설정된 가압류·압류·근저당.
유지 대상: 전입일 **이전**에 이미 설정돼 있던 근저당·가압류·신탁.

## 6. 출력 형식

케이스 1건 = JSON 파일 1개. `payload`는 아래 필드명·타입을 정확히 지켜라
(엔진에 그대로 투입되므로 오타가 있으면 파싱 실패한다).

```json
{
  "case_id": "법원약칭-사건번호뒷자리-건물명-호수",
  "description": "한 줄 요약. 계약 시점 복원 기준임을 명시",
  "label_source": "auction_outcome",
  "expected": {
    "grade": "safe | caution | risk | high_risk",
    "rationale": "그 등급인 근거. 엔진 출력이 아니라 경매 결과·전세가율 등 외부 사실로 적는다",
    "checks": {
      "deposit_to_market_ratio": "pass|warn|fail|unknown|null",
      "mortgage_ratio": null,
      "owner_mismatch": null,
      "rights_encumbrance": null,
      "residential_use": null,
      "illegal_building": null,
      "duplicate_contract": null,
      "senior_deposit": null
    }
  },
  "payload": {
    "listing_name": "건물명 호수 (소재지)",
    "deposit_krw": 275000000,
    "market_price_krw": 274000000,
    "registry_type": "aggregate_building | general_building | unknown",
    "mortgage_total_krw": 0,
    "mortgage_items": [{"amount_krw": 0, "shared_property_count": 1}],
    "registry_owner_name": "소유자A",
    "contract_owner_name": "소유자A",
    "critical_terms": [{"term": "가압류", "is_cancelled": false}],
    "building_type": "공동주택",
    "detail_use": "다세대주택",
    "illegal_building_status": "present | absent | unclear",
    "recent_jeonse_count": 0,
    "recent_jeonse_peak_12m_count": 0,
    "households": 0,
    "recent_jeonse_data_status": "complete | partial | unavailable | manual",
    "senior_deposit_krw": null
  },
  "provenance": {
    "deposit_krw": "실측 / 추론 / 가정 / 미확인 중 하나로 시작하고, 어느 서류의 어느 항목에서 얻었는지 적는다",
    "market_price_krw": "...",
    "mortgage_total_krw": "..."
  },
  "outcome": {
    "auction_case": "○○지방법원 2021타경NNNNN 부동산강제경매",
    "first_priority": "2021-04-26 가압류",
    "tenant_move_in": "2021-02-19",
    "tenant_has_priority": true,
    "tenant_claimed_distribution": false,
    "appraisal_krw": 274000000,
    "minimum_bid_krw": 3793000,
    "failed_auctions": 12,
    "note": "유찰 사유와 임차인 보증금 회수 가능성에 대한 판단"
  },
  "notes": "이 케이스가 어느 유형(A~D)이고 어느 규칙을 검증하는지"
}
```

### 필드 작성 규칙

- **`registry_type`**: 다세대·연립·아파트·오피스텔 = `aggregate_building` / 다가구·단독 = `general_building` / 등기부 미확인 = `unknown`
- **`mortgage_items`**: 근저당이 없으면 `[]`. 공동담보면 `shared_property_count`에 공동담보목록의 물건 수를 넣는다(단독담보는 1).
- **`critical_terms`**: §5로 걸러낸 뒤 남은 것만. `is_cancelled`는 말소 확인 시 `true`, 유효하면 `false`, **말소 여부를 모르면 `null`**.
- **`senior_deposit_krw`**: 다가구에서 선순위 임차인 보증금 합계. 모르면 `null`.
- **`expected.checks`**: **확신하는 항목만 채우고 나머지는 `null`.** 추측해서 채우면 없는 오답이 생긴다.
- **`households`, `recent_jeonse_*`**: 건축물대장을 확인하지 못했으면 `0` / `"unavailable"`.

### 익명화

등기부·현황조사서의 **실명은 절대 그대로 적지 않는다.** `소유자A`, `소유자B`, `임차인A`로
치환한다. 단 **일치·불일치 관계는 보존해야 한다** — 계약서 임대인과 등기부 소유자가 같은
사람이면 양쪽 모두 `소유자A`, 다르면 `소유자A`와 `소유자B`로 적는다. R3가 이름 일치 여부만
보기 때문에 관계만 유지되면 평가에 지장이 없다.

## 7. 금지 사항

1. **값을 지어내지 마라.** 사건번호, 금액, 날짜는 전부 실제로 화면에서 읽은 것이어야 한다.
   확인하지 못한 값은 `null` + `provenance`에 "미확인"으로 적는다. 그럴듯한 숫자를 채우는
   것이 빈칸보다 훨씬 나쁘다.
2. **엔진을 돌려 정답을 만들지 마라.** `expected`는 경매 결과와 전세가율 등 외부 사실에서
   도출한다. 엔진 출력을 베끼면 평가가 동어반복이 된다.
3. **경매개시결정을 `critical_terms`에 넣지 마라.** §5 위반이다.
4. **이미 확보한 인천 2021타경521675는 건너뛴다.**

---

## 8. 사이트가 막히거나 조작이 안 될 때

법원경매정보는 JavaScript 기반이라 자동 조작이 실패할 수 있다. 그런 경우:

- **실패했다고 보고하라.** 다른 사이트의 요약 정보로 대체해 채우지 마라. 민간 경매 사이트의
  가공된 데이터는 원본과 다를 수 있고, 출처 추적이 불가능해진다.
- 물건 목록 탐색만 안 되고 개별 사건 조회는 되는 경우, 사건번호를 알면
  **경매사건검색**(법원 + 사건번호)으로 직접 접근할 수 있다.
- 서류가 PDF 뷰어로 열려 텍스트 추출이 안 되면, 화면을 읽어 값을 옮겨 적고
  `provenance`에 "현황조사서 화면 판독"이라고 명시하라.

## 9. 최종 보고

케이스 JSON 4개와 함께 다음을 보고한다.

- 유형 A~D 중 **채운 것과 못 채운 것**, 못 채운 이유
- 조사했다가 **버린 물건과 사유** (유치권, 지분, 서류 미열람 등)
- 각 케이스에서 **확인하지 못한 필드 목록**
- 사이트 접근에 실패한 구간이 있으면 그 지점

파일은 `eval/cases/real/<case_id>.json`으로 저장한다.
저장 후 `PYTHONPATH=. python eval/validate.py`를 실행해 스키마 검증을 통과시켜라.
